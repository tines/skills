# Workflow discovery

Establish the workflow’s outcome before designing steps. Ask only for decisions that materially affect the implementation:

- What event or schedule starts the work
- What input is available
- Which connectors and records are authoritative
- What transformation or decision is required
- What output or side effect marks success
- How failures should be handled

When suggesting ideas, ground them in connectors the user can actually use and favor repetitive, time-sensitive work with a clear measurable result. Produce a brief that is specific enough to build without restating the conversation.
